## 第 0 页：全员「第一天要做的事」

1. **第一次登录后马上自己改密码**：地址栏输入 `/update-password`。系统**不会强制**你改，不改就一直是店主知道的那个密码。
2. 自己的账号只给自己用；离开岗位时不用退出，但不要把密码告诉别人；忘了密码或换人 → 告诉店长。
3. 你的角色能做什么（一行表）：

   | 角色 | 能做 | 不能做 |
   |---|---|---|
   | ホール（服务员） | 点单、加菜、写备注、打印账单 | 收款、取消已发送的订单、拆单、合算 |
   | レジ担当（收银员） | 上面全部 + 收款、拆单、合算、取消、开班、交班 | 看报表、管账号 |
   | 厨房 | 看单、上菜、确认取消单 | 点单、收款 |
   | 店長 | 全部 + 报表、账号、平板、二维码 | — |

4. 每天开店时：**先点一下收银台的画面**（浏览器要被点过一次才会出声，否则第一个呼叫没有声音）。
5. 出问题先看「出问题怎么办」那一页，再找店长。
6. （12/19 切换后）**试营业时改过的密码在正式系统里不通用**，12/20 第一次登录用新发的初始密码，再改一次。← *取决于你对"试营业数据方案"的确认*

## 第 1 页：ホール（服务员）

- **登录和画面**：打开哪个地址、登录后看到什么；没有人开班时看到的提示是什么意思（服务员没有自己的开班，等收银员开班）。※画面确认
- **点单**：选桌 → 点菜品（点一下加 1 份）→ 确认发送到厨房。人数、堂食 / 外带的选择。※画面确认
- **写备注**：服务员画面点菜品只会加 1 份，没有备注对话框；先加上，再点购物车里那一行的编辑图标写备注。已发到厨房的行**备注不能再改**。
- **规格和加料**：加料是单独的一行「主菜名・加料名」；菜单里没有加料自己的卡片。
  - 和主菜一起加：选主菜 → 勾加料。
  - **客人后来才要加料**：再点同一道菜 → 勾加料 → 勾「トッピングだけを追加する」。
  - **改了主菜的数量，要自己检查加料行**（已发送的订单里加料数量不会跟着变）。
- **加菜**：打开那张桌的订单继续加；新加的部分确认后才发到厨房。
- **未确认的订单换桌**：还没发送的内容，换到已有订单的桌时会问「未確定の注文があります」：追加到那张桌，或取消。
- **外带**：外带的税率不同（食品 8%），订单类型选对；外带用外带桌。※画面确认
- **打印账单**：服务员可以打印账单给客人看，**不能收款**，客人到收银台付。
- **呼叫结账的提示**：提示条和桌卡上的铃铛是什么意思；打开那张桌只是让提醒安静，打印账单 / 付款后才消失。
- **不能做的事和原因**：取消、减菜已发送的内容、收款、拆单 → 找收银员。
- **顾客自助点餐时服务员要知道的**：顾客扫二维码或用平板下的单会出现在同一张桌的订单里；顾客不能改已发送的内容，要改找店员；酒类会问年龄。

## 第 2 页：レジ担当（收银员）

- **开班**（每天第一件事）：输入开班时钱箱里的现金 → 开班。前一天忘了交班时，开班画面会要求勾选确认，交班画面会显示「前回までの未締め伝票」：是什么意思、该怎么做。※画面确认
- **点单**：和服务员相同；另外**双击**菜品可以打开对话框写备注、选规格和加料（单击 = 直接加 1 份）。
- **收款**：
  - 选支付方式、输入金额、完成、打印小票、钱箱打开。※画面确认
  - **找零只有现金有**：卡、PayPay 等无现金支付必须是正好的金额，系统不让多收。
  - **几个人分着付（割り勘）**：**不要拆单**，在收款画面一次输入多种支付方式（现金 + 卡等），一张小票。要一次输入全部支付。
- **会計分割（拆单）**：只在客人要**各自的账单和小票**时用；各账单独立计税，合计可能和原来差 ¥1，这是正常的。拿不准就不拆。
- **会計合算（合并）**：合算后按合算金额计税，可能比分别结账多或少 ¥1，正常。怎么合、怎么取消合算。※画面确认
- **取消和减菜**：
  - 已发送的订单最后一行删不掉；整张不要了，到「伝票」画面用「取消」（是否要写理由 ※画面确认）。
  - 取消后厨房会收到取消单；只取消厨房实际收到过的内容。
- **小票**：重新打印；小票上的税率区分（8% 的标记）、登録番号在哪。打印机没纸 / 没反应时怎么办（见「出问题」页）。
- **交班**（每天最后一件事）：数钱箱 → 输入各支付方式的实际金额 → 画面上的「应有金额 = 开班金额 + 当班现金收款 − 找零」→ 差额怎么处理、写在哪 → 交班。**不交班第二天会有提示。**※画面确认
- **KOT 出错提醒**：收银台弹出"厨房单没发出去"时怎么做（告诉厨房口头下单，再告诉店长）。※画面确认
- **不能做的事**：看报表、管账号 → 店长。

## 第 3 页：厨房

- **登录**：厨房账号登录后直接进厨房屏幕；这台设备一直开着这个画面。
- **看单**：新单、加菜单、改单的样子；计时变红 = 做得慢了。屏幕会自己更新，最多 30 秒；不用手动刷新。
- **单独一行的「主菜名・加料名」**：意思是给**已经下过的那道主菜**追加加料；不清楚是哪一份就问点单的人。
- **做完 / 上菜**：点哪里表示这张单做完了。※画面确认
- **点某一行的标记**（绿色删除线）：**只在这台设备上有效**，换设备看不到，只是自己做记号。
- **取消单**：出现取消 / 部分取消的单 → 确认内容 → **马上点「确认」**（只保留 3 小时）。取消单的计时是黑色。
- **屏幕没有新单**（但店里明明在点）：先看右上角的连接状态 / 刷新一次 → 还不行，告诉收银员改口头下单，找店长。※画面确认
- **不能做的事**：点单、收款。

## 第 4 页：店長

- **每天**：
  - 早上 8 点有一封服务器日报邮件；**没收到 = 服务器可能有问题**，按「出问题」页处理。
  - 确认收银员开班、闭店后交班；看当天的差额。
  - 营业数据和报表在哪看（`/ury`）；谁能看（只有店长）。※画面确认
- **桌子和自助点餐**：
  - 桌上二维码：贴在哪张桌就是哪张桌，不能换位置；坏了、丢了怎么重新打印（Desk 的二维码打印页）。**桌子名不能改**（改了二维码作废）。
  - 平板：每台固定一张桌；开店时各看一眼是不是等待画面；重新登记的方法（设置链接）。※画面确认
  - 桌的自助点餐什么时候开放、什么时候关闭（开桌时长）。※画面确认
- **账号**：
  - 新人：现在由我用数据包加（加进 Excel 再导入），或在管理画面里建；发初始密码，叮嘱第一天改。
  - 离职 / 忘记密码 / 密码被人知道：停用或重设（停用后那个人的登录全部失效）。
  - **抽查**：新人第一周内问一句"密码改了吗"。
- **菜单**：停售一道菜、改价格的做法；改价格以 Excel 为准，再导入（避免两边不一致）。※画面确认
- **机密由店长保管**：二维码密钥、备份加密密码、服务器密码都在密码管理器里；不告诉店员；不发到群里。
- **更新系统**：只在闭店后，由我来做；做完要让所有平板刷新一次。
- **练习用的地址**：`http://ury.lan:8081` 是练习用的（不是真的账），新人培训在那里做。← *取决于"试营业数据方案"的确认*

## 第 5 页：出问题怎么办（全员，贴在收银台）

原则：**先让客人能点菜和付钱，再修系统。** 每种情况写三行：看到什么 → 先做什么 → 找谁。

| 情况 | 先做什么 |
|---|---|
| 顾客的手机扫码打不开 | 店员用收银台或自己的设备替他点；平板不受影响。告诉店长（多半是互联网或 Tunnel） |
| 桌上平板不动 / 显示出错 | 下拉刷新一次；不行就由店员点单；告诉店长 |
| 厨房屏幕没有单 | 口头或手写下单；收银员看有没有出错提醒；告诉店长 |
| 小票打不出来 | 看打印机的纸和电源；收银电脑上 QZ Tray 是否在运行；先手写收据，之后补打 ※画面确认 |
| 钱箱不开 | 用钥匙开；检查钱箱的线是不是接在打印机上 |
| 收银台打不开 / 很慢 | 刷新（Ctrl+Shift+R）；换另一台设备登录；还不行 → 服务器故障 |
| **整个系统打不开（服务器故障 / 停电）** | 改用**纸质应急流程**：手写点菜单（桌号、菜名、数量、时间）、手写收据、现金和卡的记录；恢复后由收银员补录。服务器的电源键在哪、谁可以按（只有店长） |
| 互联网断了 | 店内的收银台、平板、厨房屏幕**照常能用**；只有顾客手机扫码不行；刷卡 / 二维码支付的终端可能不能用 → 只收现金，并告诉客人 |
| 金额看起来差 ¥1 | 拆单 / 合算后的正常现象（每张账单每个税率只算一次税） |
| 点错了、已经发到厨房 | 服务员不能取消 → 找收银员 |

最后一行：店长的电话、开发（我）的联系方式、「什么时候可以直接打电话」。

**纸质应急流程本身**（手写点菜单和收据的样式、恢复后怎么补录、税额怎么算）是 `launch-plan.md` 2.3 里 12/11 的另一项，这一页只指向它；补录的规则要和税理士的回答一致。
