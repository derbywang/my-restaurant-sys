# 日本消费税与日元设置 设计

- 代码基础：my-restaurant-sys（URY 3.0.0-beta.1 / ERPNext v15）
- 状态：设计稿（经营决定已确认，实现细节要先调查 ERPNext 源码再确定）
- 日期：2026-11-01
- 注意：本文不是税务意见。上线前请税理士确认税率、尾数处理和小票的记载内容。

## 1. 经营决定（已确认）

| 项目 | 决定 |
|---|---|
| 单型 | 有堂食，也有外带 / 外卖配送（Take Away、Delivery、Phone In、Aggregators） |
| 价格规则 | **不含税价相同**：菜单录入不含税价；堂食和外带的含税价不同 |
| 酒类 | 供应（不论堂食还是外带都是 10%） |
| 适格请求书 | **已登记**（有 T + 13 位的登记号）→ 小票按适格简易请求书的格式打印 |
| 尾数处理 | **舍去**；每张账单按税率各处理一次 |
| 币种 | JPY（不显示小数） |

## 2. 税率规则

| 类别 | 现在 | 2027-04-01 ～ 2029-03-31（法案审议中，尚未成立） | 2029-04-01 起 |
|---|---|---|---|
| 堂食（店内飲食） | 10% | 10% | 10% |
| 外带、外卖配送的食品 | 8% | **1%** | 8%（按现行法案） |
| 酒类（所有单型） | 10% | 10% | 10% |
| 非食品（周边商品等） | 10% | 10% | 10% |

- 税率由 **单型 × 商品类别 × 交易日期** 决定。
- 1% 的法案目前（2026-10-26）还没有成立。法案成立后，只需**补充按日期生效的数据**，不需要改代码（见 4.2）。

## 3. 现状的问题

1. 现在用的税是 **5%**（初始化向导默认带出的印度 GST 税率），必须替换。
2. URY **不会按单型切换税率**：URY Restaurant 上只有一个默认税模板。
3. ERPNext 在计算税额时，是**四舍五入**（`flt`）到币种精度，**没有“舍去”的选项**，需要确认它的计算方式后再做定制。
4. JPY 币种的格式会显示小数（例如每日损益打印出来是 `¥ 1,234,567.50`）。
5. 小票不符合适格简易请求书的格式（没有登记号，没有按税率分开的金额和税额，没有轻减税率的标记）。
6. 初始化向导里，菜单页的税率默认是 5%。

## 4. 设计

### 4.1 税的结构（ERPNext 的标准机制）

**税模板**（Sales Taxes and Charges Template）：一个模板 `消費税（日本）`，**按税率分成多行**，这样尾数可以按税率分别处理。

| 行 | 内容 | 默认税率 | 科目 |
|---|---|---|---|
| 1 | 消費税 10% | 10 | 仮受消費税（可以按税率分科目，也可以共用一个，由会计决定） |
| 2 | 消費税 8%（軽減） | 0 | 同上 |
| 3 | 消費税 1%（軽減・時限） | 0 | 同上 |

- 所有行都**不勾选** “Is this Tax included in Basic Rate”（因为价格规则是“不含税价相同”）。
- 每个商品实际适用哪一行，由下面的 **Item Tax Template** 决定（把其他行设成 0%）。

**Item Tax Template（商品税模板）**

| 名称 | 10% 行 | 8% 行 | 1% 行 |
|---|---|---|---|
| 標準 10% | 10 | 0 | 0 |
| 軽減 8% | 0 | 8 | 0 |
| 軽減 1% | 0 | 0 | 1 |

**Tax Category（税类别）**：`店内飲食`、`テイクアウト`

### 4.2 每个商品的税设置（Item → Taxes 子表）

ERPNext 的 Item 有一张 Taxes 子表，字段包括 `item_tax_template`、`tax_category`、`valid_from`。交易时，按 **单据的 tax_category** 和 **交易日期 ≥ valid_from** 自动选择商品税模板。

| 商品类别（按 Item Group 统一设置） | 税类别 | 生效日期 | 商品税模板 |
|---|---|---|---|
| 食品 | 店内飲食 | — | 標準 10% |
| 食品 | テイクアウト | — | 軽減 8% |
| 食品 | テイクアウト | 2027-04-01（法案成立后添加） | 軽減 1% |
| 食品 | テイクアウト | 2029-04-01（同上） | 軽減 8% |
| 酒类、非食品 | 店内飲食 / テイクアウト | — | 標準 10% |

- 尽量**按 Item Group 设置**（ERPNext 的 Item Group 也有 Taxes 子表，商品会继承），这样新增菜品时不用逐个设置。
- 将来税率变动时，只需要**添加带生效日期的行**（这是数据，不用改代码）。

### 4.3 按单型设置税类别（需要二次开发）

- 在 POS Invoice 的钩子里（`ury/ury/hooks/ury_pos_invoice.py`），按 `order_type` 设置 `tax_category`：
  - `Dine In` → `店内飲食`
  - `Take Away` / `Delivery` / `Phone In` / `Aggregators` → `テイクアウト`
- 每行商品的 `item_tax_template` 按新的税类别和交易日期**重新取得**，然后重新计算税额。
  订单中途改单型时（如果有这种操作）也要重新计算。
- `sync_order` / `price_items_for_invoice` 生成商品行时，要保证适用的是按 4.2 规则取得的商品税模板，而不是保留旧的值。
- 实现前先确认 ERPNext 的 `get_item_tax_template`（或同等函数）的选择逻辑，以及 POS Invoice 是否有 `tax_category` 字段。

### 4.4 尾数舍去（需要二次开发）

- 规则：**每张账单、每个税率计算一次**税额：`税额 = floor(该税率的不含税金额合计 × 税率)`。不允许按商品分别计算再相加。
- ERPNext 默认按商品计算税额，再把税行的合计**四舍五入**到币种精度。需要先调查以下几点，再决定实现方式：
  - `erpnext/controllers/taxes_and_totals.py`（服务器端）和 `taxes_and_totals.js`（前端）的计算方式
  - Accounts Settings 里的 “Round Tax Amount Row-wise”（`round_row_wise_tax`）设置的作用
  - 推荐做法：在服务器端的 POS Invoice 钩子里，在 ERPNext 计算之后，**把每个税行的税额改成“该行对象金额 × 税率后舍去”**，再更新合计；**收款金额、找零、交班金额都以服务器端的计算结果为准**
  - 收银端（pos）和服务员端显示的合计，要和服务器端的结果一致（需要确认前端是自己计算，还是用服务器返回的值）
- 舍去的方法以后可能要改（比如改成四舍五入），所以做成**可以配置**（放在 POS Profile 或 URY 的设置里，默认“舍去”）。

### 4.5 JPY 的格式与精度

- Currency `JPY`：确认 `smallest_currency_fraction_value = 1`，`number_format` 设为不显示小数（如 `#,###`）。
- System Settings：确认 `currency_precision` 的值（JPY 的门店设为 0）。修改前要评估对其他币种和已有数据的影响。
- 圆整合计（Rounded Total）：日元本来就没有小数，确认 `disable_rounded_total` 等设置是否需要调整。
- 确认每日损益的打印不再出现 `.50` 这样的小数。

### 4.6 小票（适格简易请求书）

在 POS Invoice 用的打印格式中（如果已有 URY 的打印格式，就以它为基础新建一个），包含以下内容：

1. 适格请求书发行事业者的名称（公司 / 门店名）和**登记号（T + 13 位）**
   - 登记号保存在哪里，要先确认（Company 的 `tax_id`，或者新增一个自定义字段）
2. 交易日期时间
3. 交易内容（商品名、数量、金额）；**轻减税率的商品加上 ※ 标记**，并注明“※は軽減税率対象”
4. **按税率分开的对象金额**（10% 对象 / 8% 对象 / 1% 对象）
5. **按税率分开的消费税额**（或适用税率；建议两者都印）
6. 合计、收款（お預かり）、找零（お釣り）
7. 单型（店内 / お持ち帰り）

- 不需要印收件人名称（这是适格简易请求书的特点）。
- 按税率分开的金额要和 4.4 的计算结果一致。

### 4.7 初始化工作

- 停用或删除现在的 5% 税模板，按 4.1 新建税模板、商品税模板和税类别。
- 设置 Item Group 的 Taxes（食品、酒类、非食品）。
- URY Restaurant 的 `default_tax_template` 改成新的模板。
- 把这些初始设置做成**迁移补丁 + after_install**（和多语言阶段 2 的做法一样），只在国家是日本的站点执行；科目在实现时确认。
- 初始化向导：国家是日本时，菜单页的税率默认用 10%，或者不显示这个输入项，改为采用以上设置。

## 6. 验收用例

| 编号 | 场景 | 预期结果（不含税价） |
|---|---|---|
| J1 | 堂食：寿司 ¥1,000 + 啤酒 ¥500 | 10% 对象 ¥1,500，消费税 ¥150，合计 ¥1,650 |
| J2 | 外带：寿司 ¥1,000 + 啤酒 ¥500（2027-03-31 之前） | 8% 对象 ¥1,000 税 ¥80，10% 对象 ¥500 税 ¥50，合计 ¥1,630；寿司有 ※ 标记 |
| J3 | 外带：寿司 ¥333 × 1 + ¥333 × 1（尾数） | 8% 对象 ¥666 → 税 floor(53.28) = ¥53（**不是**按商品计算再相加的 ¥26 + ¥26 = ¥52） |
| J4 | 堂食开单后改成外带（如果有这种操作） | 税率重新计算 |
| J5 | 交易日期是 2027-04-01（已添加 1% 数据时） | 外带食品适用 1%，酒类仍然 10% |
| J6 | 打印小票 | 包含 4.6 的全部内容，按税率分开的金额与 J1～J3 一致 |
| J7 | 交班 | 应收金额和小票、账单的合计一致（没有尾数差） |
| J8 | 金额显示 | 收银端、管理后台、打印都不显示日元的小数 |
