# 小票打印机和钱箱（iPad 收银台）

状态：2026-11-16 写，11-17 更新：打印核心（`ury/printing/`）、服务器接口（`ury/ury/api/receipt_print.py`）、收银台的按钮和付款后开钱箱、断线提示条和屏幕常亮、厨房出错提醒的第二条通道已做，并用假打印机测过；**没有任何一步在真实打印机上跑过**，打印机预计 11/27 前到货。标记：【已读代码】【已测逻辑（假打印机）】【待打印机】【估计】。

## 1. 为什么和原来的设计不一样

原设计是电脑上装 QZ Tray，浏览器连它打印（`self-order-design.md` 9.5）。**收银台改成 iPad + Safari，iPad 不能装 QZ Tray**；厨房只看 iPad 屏幕，不打印。所以：

- **服务器直接把小票发给打印机**（店内局域网）：iPad 只点「印刷」，Safari 不参与，没有混合内容、证书、跨域的问题。
- 小票沿用 `ury_jp_receipt.html`（`領収書` / `ご請求明細`），服务器把它画成黑白图片再发。日文字体在服务器上，不靠打印机内置字库。
- 钱箱 CD-B3336W 接在打印机的钱箱接口上，**开箱指令放在打印任务里**（打印机自己不会开）。
- 原来的 QZ、CUPS 路径保留不动（有电脑的店仍可用），新路径是 POS Profile 上多选一项。
- **厨房单不在纸上打印**：KOT 的纸质打印设置项保留，默认关（`URY Printer Settings` 的 `custom_kot_print`，本来就是逐项勾选）。

## 2. 设置（打印机一台一条记录）【已写好，随这次 migrate 上线；2026-11-17】

新的 DocType **URY Receipt Printer**，POS Profile 里选一台：

| 项 | 说明 |
|---|---|
| 名称 | 例如「レジ」 |
| 地址 | 打印机的固定 IP（或 `ury-printer.lan`），不带 `http://` |
| 方式 | **ePOS-Print**（首选：打印机会回报缺纸、开盖等状态）／**ESC/POS（9100 端口）**（备选：没有回报，但打任务前会问一次纸传感器）。每台打印机选一种 |
| 端口 | ePOS-Print 默认 80（新机型据说是 80/443，不是旧的 8008/8043，到货实测）；ESC/POS 默认 9100 |
| 纸宽 | **80 mm（实际装的纸，2026-11-17 更正）**：可印 72 mm，576 点；**也支持 58 mm**（可印 48 mm，384 点；需要给打印机装 58 mm 托架，打印机本身没有纸宽设置项）。在表单里选「80」 |
| 有钱箱 | 勾选后才会发开箱指令 |
| 开箱的针脚和时长 | 默认针脚 2、50 ms 通 / 500 ms 断（`ESC p 0 25 250`）；到货实测，不开就试针脚 5 |
| 启用 | 关掉后打印直接报"没有设置打印机"，不会悄悄去走别的路径 |

另有 **「开钱箱的记录」**（谁、几点、为什么：「会計完了」「手動」、成功与否），收银员按「引き出しを開ける」时记一条。

## 3. 什么时候打印、什么时候开钱箱

| 动作 | 打印 | 开钱箱 |
|---|---|---|
| 服务员或收银员打印 **ご請求明細**（客人账单） | 打印 | **不开** |
| **会计完成**（`make_invoice` 成功），支付里有**现金**收入或有找零 | 不自动打印（領収書按需在「伝票」里打印，和现在一样） | **开**（只开，不出纸） |
| 会计完成，全部是卡 / PayPay 等无现金支付 | — | 不开 |
| 在「伝票」里补打已付款的 **領収書** | 打印 | **不开**（会计时已经开过了） |
| 收银员按「引き出しを開ける」（兑零钱等） | 不打印 | 开，并记一条记录；只有能收款的人看得到这个按钮 |
| 厨房单 | 不打印（厨房看屏幕） | 不开 |

打印失败（缺纸、盖子没盖、连不上）：画面上提示一句日文说明原因，**不影响会计本身**（会计已经提交）。开钱箱失败同理：提示「引き出しが開きませんでした。鍵で開けてください」。

## 4. 打印机放哪里、怎么连网

### 4.1 位置【估计，到货后现场定】
- 放在收银台，**钱箱旁边**：钱箱线（RJ-12）长度有限，先量好再放。
- 靠近 Wi-Fi 路由器或有网线能到的地方；通风，不放在水、油、热源旁（离厨房灶台远）；纸出口朝向收银员，客人拿不到。
- 电源用随机的 USB-PD 适配器，插在有 UPS 的插座上最好（停电时路由器和打印机一起撑一会儿）。
- 纸：**80 mm**（打印机里装的是 80 mm，没装 58 mm 托架，机器本身没有纸宽设置项；先前误写成 58 mm，印出来只占纸的左边 2/3）。用热敏纸（有涂层的一面朝外，装反了不出字）。**要改用 58 mm 纸：装 58 mm 托架，表单里纸宽改选「58」**，不用改别的。

### 4.2 有线还是 Wi-Fi
- **到货确认：打印机背面有网口，用有线**（2026-11-17）。收银台的打印不能失败，网线比 Wi-Fi 稳；网线接路由器（或交换机），不用 Wi-Fi。
- 打印机的 IP 在路由器上做 DHCP 预留（见 4.3），把 IP 填进「URY Receipt Printer」的地址（IP 由店里给我）。
- （备用：改用 Wi-Fi 时连**店内网络**，不是访客 Wi-Fi，服务器要能连到它；平时不用。）

### 4.3 固定 IP
- **首选在路由器上做 DHCP 预留**（路由器管理页：按打印机的 MAC 地址固定一个 IP，例如 192.168.x.20）；服务器和 iPad 同理，已经要做（`server-setup.md` 1.1）。
- 备选：在打印机的网页设置里设静态 IP（用浏览器打开打印机的网址，登录 Web Config；初始账号和密码看打印机的说明书）。
- 记下 IP，填进「URY Receipt Printer」的地址；**换了地址要改这里**。

### 4.4 服务器到打印机
- 服务器在 Docker 容器里，访问店内局域网的地址没问题（出站流量）。【待打印机：实测从 backend 容器能否连到打印机的 80 / 9100 端口】
- 防火墙：路由器不对外开放；打印机的 9100 端口只在局域网（`launch-plan.md` 2.6）。
- 打印机的 Web Config 里改一次默认的管理员密码。

## 5. 打印机到货后第一天的验证清单【待打印机】

按顺序做，每项写下结果（端口、参数、秒数）。**先做到第 7 项再接 iPad**。

1. 开箱，装纸（先看纸宽），接电源和钱箱线，通电；打印自检页（关机状态下按住 FEED 键开机），看**固件版本**（Epson 的 TM-m30III 固件最新是 13.19，旧的先更新）。
2. **用网线接入店内网络**（已确认有网口、用有线）；纸是 80 mm，装好纸后打印自检页，确认字宽和纸宽对得上。
3. 用手机或电脑打开打印机的网页设置（Web Config），**设固定 IP**（或在路由器做 DHCP 预留），改管理员密码；看 **ePOS-Print 的设置在不在、用哪个端口**（旧机型 8008/8043，新机型据说 80/443）。
4. 在**服务器的 backend 容器里**：`ping` 打印机、测 80 和 9100 端口是否通（`dc exec backend bash -c 'timeout 3 bash -c "</dev/tcp/<IP>/80" && echo ok'`）。
5. **ePOS-Print**：发一条最简单的任务（一行字 + 切纸），看返回的状态；再发我们的**日文小票**（`bench execute` 里调打印模块，纸宽选 **80**）：看**字大小和清晰度（80 mm 上 12px 的字约 22 个字一行）、品名是不是单独一行并且长名字正常换行、金额是不是靠右对齐、登録番号和税率别合计有没有被切掉、領収書的印纸欄是否在右边完整**、切纸位置。
6. **ESC/POS（9100）**：发同样的内容，对比；**换另一种方式后图片是否一样**（这能验证 ePOS-Print 的图片数据格式我写对了没有）。
7. **钱箱**：发开箱指令，**先试针脚 2**，不开再试针脚 5；记下能用的参数；确认钱箱线接牢。
8. 在设置里选定一种方式，`ury-datapack` 导入的 POS Profile 填好打印机；从收银台 iPad 试：**打印 ご請求明細（钱箱不能开）**；**一笔现金会计（钱箱要开）**；**一笔刷卡会计（钱箱不能开）**；补打 領収書（钱箱不能开）；「引き出しを開ける」（要开并记一条）。
9. **故障测试**：拔掉打印机网线或电源再点打印，看收银员收到什么提示；打开盖子点打印；把纸抽掉点打印；恢复后能不能继续。钱箱打不开时的提示。
10. **iPad 实测**：从点击到出纸几秒；连打 5 张；同时两台设备打印会不会乱（服务器排队）。
11. **长时间**：连续开 2 小时看会不会断；打印机重启一次后能不能自己连回；拔掉网线 30 秒再插回，看打印机能不能自己恢复。
12. **让税理士看一张实际小票**（印纸、登録番号、税率区分，等他的回答）。
13. 数字写回本文：端口、针脚、脉冲时长、出纸秒数、能不能连续打印。

**如果 ePOS-Print 的图片格式不对**（第 5、6 项对不上）：先用 ESC/POS 方式开店（它和格式问题无关），ePOS-Print 的图片编码我再对着 Epson 的手册改。

## 8. 画面を点けたままにする：`http://ury.lan` では Wake Lock は効かない（2026-11-17 評価）

**事実（Web の仕様）**：`navigator.wakeLock`（ブラウザに「画面を消さないで」と頼む機能）は**安全なページ（HTTPS、または `localhost`）でしか使えない**。店内の iPad・厨房タブレットは `http://ury.lan` を開くので安全なページではなく、**Wake Lock は使えない**（ブラウザにその機能が現れない）。コードはそれを「使えない」と受け取って**何も言わずに続ける**（エラーにも警告にもならない）ので、画面が消えるかどうかは **端末の設定だけ**で決まる。顧客のスマホ（Cloudflare 経由の HTTPS）は関係ない（Wake Lock を使うのは POS と厨房画面だけ）。

**対策（採用）：設定で消えないようにする。** 3 つとも要る。
1. **自動ロック＝なし**：設定 > 画面表示と明るさ > 自動ロック > **なし**（Android は「画面消灯」を最長にし、開発者向けオプションの「スリープモードにしない（充電中）」を入れる）。
2. **電源につないだまま**：レジの iPad も厨房タブレットも、営業中は**充電ケーブルをつなぎっぱなし**（スタンドの近くにコンセントがあること。電池は停電の保険）。省電力モードは**オフ**（オンだと自動ロックが 30 秒に戻る）。
3. **アクセスガイド（Guided Access）**：設定 > アクセシビリティ > アクセスガイド。誤ってホームに戻ったり別アプリを開いたりするのを防ぐ。アクセスガイドには**「画面の自動ロック」の別設定**があるので、アクセスガイドの設定にある「画面の自動ロック」も**なし**にする（どちらが優先されるかは iPadOS のバージョンで違うかもしれないので、両方なしにして、実機で確かめる【待 iPad】）。

**他の案と、採らなかった理由**
| 案 | 効くか | 採らない理由 |
|---|---|---|
| 店内 LAN も HTTPS にする（店内用の証明書を各端末に入れる） | 効く（Wake Lock が使える） | 端末ごとに証明書プロファイルの設定が要り、期限が来ると全部止まる。開店前にやる作業が増える。**開店後に困ったら検討** |
| 「NoSleep」のように見えない動画をずっと再生して画面を点ける | 効くことが多い | iOS の更新で効かなくなることがある。電池も食う。設定で足りるので入れない |
| 画面が消えたら人が起こす | — | 注文を逃す。却下 |

**真機で確かめる（到着した日）**：`printer.md` 5 節のあとに、**iPad を触らずに 10 分置く**（亮度 50%、電源接続、アクセスガイドの中）。画面が消えない・暗くならない、と**その後で POS が動く**（赤い帯が出ていない、ログインが切れていない）の 2 つを確認して、結果をここに書く【待 iPad】。確認できるまで、レジ担当の朝の手順に「画面が点いているか見る」を入れてある（`docs/training/ja/00-はじめに.md`）。

**もう一つの落とし穴：** 同じ理由（安全なページではない）で、Service Worker・クリップボード API など「安全なページ限定」の機能は店内では使えない。**今のコードは使っていない**。新しく使う機能を足すときは、`http://ury.lan` で動くかを先に確かめる。

## 9. 打印机的选择改了以后，已经登录的端末怎么办（2026-11-17）
POS 登录后把 POS Profile 缓存在浏览器里（`sessionStorage`）。**每次打开 POS 都会向服务器再问一次“怎么打印”（`print_type`，只这一个字段；`pos/src/lib/print-type.ts`）**，所以给 POS Profile 选好（或换掉）打印机之后，**已经登录的 iPad 重新打开或刷新页面就生效，不需要清缓存、不需要重新登录**。服务器问不到时沿用缓存里的值。（浏览器测试时发现：改之前，已登录的窗口会继续用浏览器自带的打印页，账单标成“已印”却没有送到打印机。）
注意：改的是 `print_type`；打印格式、QZ 地址等其他项目仍然来自登录时的缓存，要换需重新登录。

## 10. 80 mm 和 58 mm 的小票（2026-11-17；实际用 80 mm，58 mm 备用）

**实际装的是 80 mm 纸，可印 72 mm = 576 点；58 mm（可印 48 mm = 384 点）也支持。** 小票模板 `ury_jp_receipt.html` 沿用，**58 mm 窄纸**（页面宽度 ≤ 400 px，即 384 点）时每个品目分成两行：**品名独占一行**（长名字换行），**下一行右对齐写“数量 × 单价”和金额**；**80 mm 纸是一行**（品名、数量×单价、金额在同一行；带加料的长名字在「・」处断开，加料落到下一行）。登録番号、税率别合计（10% / 8%※）、领收书的印纸欄（26 mm 宽，靠右）都在 48 mm 里放得下（用假数据画出来看过，`ury/printing/test_printing_core.py` 里有测试）。

**一个以前没发现的问题（这次画 58 mm 时看到）**：`frappe.get_print` 返回的是带外壳的整页（顶部的「Print」「Get PDF」条、灰色的边、纸张大小的白框和内边距、每个表格单元格 6px 的内边距），直接画成图片，小票会被推到右边、被切掉右边一截，顶部还有那一行字，行距也很松——**80 mm 也是一样**。已改：`bitmap.fit_to_paper` 去掉外壳并把小票的宽度设成纸的可印宽度（测试用 Frappe 真实的样式复现并锁住）。浏览器测试（假打印机）只看了日志里的尺寸，没有看图，所以没发现。

**改了模板，站点要 migrate 才会写回**（`refresh_receipt_format`）；`deploy_check` 的「receipt format」在写回之前会报 FAIL（站点的模板和文件不一样）。

**ESC/POS 光栅图的宽度**：不写死 576，随纸宽走（`bitmap.printable_dots` → `to_raster` → `GS v 0` 的 xL xH；ePOS-Print 的 `<image width>` 也一样）；测试：58 mm 发 48 字节/行，80 mm 发 72 字节/行。

## 12. 更正和第二轮（2026-11-17）：纸是 80 mm

第一轮我按 58 mm 做了（384 点宽的小票），而打印机里装的是 **80 mm 纸**（没装 58 mm 托架，机器本身没有纸宽设置项），小票只印在左边 2/3，右边空白。**第 11 节的网络、端口、ePOS / ESC/POS 的结果与纸宽无关，仍然有效；小票的外观和耗时按 384 点的算，不能用于 80 mm。** 改成：URY Receipt Printer 的纸宽选 **80**（地址 192.168.40.178）；小票用 576 点宽（单行布局）。第二轮的结果见下。

## 13. 纸宽在哪里设、怎么看对不对（2026-11-17）

**位置**：Desk 里的「URY Receipt Printer」，字段 **「Paper Width (mm)」（`paper_width`）**，选 **80 或 58**；列表（`/app/ury-receipt-printer`）里直接有这一列。能打开它的是店长（URY Manager）、URY Admin 和 System Manager（收银员和服务员没有）。POS 画面里没有这个设置。

**「テスト印刷」按钮**（打印机记录页的顶部按钮）：用**已保存的设置**打一张测试页——一个和“可印宽度”一样宽的框、左右各一个标记（◀ 左 / 右 ▶）、毫米刻度尺、当前纸宽（mm 和点数）、打印机地址和方式。**判断**：框的左右两边都贴到纸边、右边的「右 ▶」看得见 → 设置对；右边被切掉 → 设置比纸宽（比如纸是 58 但选了 80）；右边空出一块 → 设置比纸窄（比如纸是 80 但选了 58）。不会开钱箱。只有能改这条打印机记录的人能按。代码：`receipt_print.print_test_page`、`ury/printing/testpage.py`、`ury_receipt_printer.js`；测试：`test_printing_core.py` 的 `TestThePaperWidthTestPage`（框顶到纸边、整条框封闭）和 `test_printer_doctypes.py` 的 `TestTheTestPrint`（对着假打印机，80 发 576 点、58 发 384 点，收银员和服务员被拒绝，打印机没开时是一句话）。

**向导 / 数据包加“打印机”一步的评估**见 `launch-plan.md` 0.0 的决定记录。

**第二轮之后的补记（2026-11-17 晚）：** 重启打印机后「テスト印刷」成功。刚才的故障原因：**盖子开过，加上积压的任务，打印机进入出错状态，请求超时（ReadTimeout）**，所以屏幕上看到“接続できません”，其实打印机是通的，只是不回应。**处理顺序**（已写进培训材料 `docs/training/ja/05-困ったとき.md`）：看指示灯 → 检查盖子和纸 → 拔电源等 10 秒再插上 → 仍不行找店长。重启会清掉打印机里积压的任务，出不来的单要在画面上重新印；盖子盖上后积压的单也可能自己打出来，同一张单出两张时只给客人一张。**待办**：到时候读一下状态（ePOS 的 `status`）里“出错”位，让提示更准确——现在的提示在超时时只会说“接続できません”。
