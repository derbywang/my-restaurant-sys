# 正式站点导入手顺（数据包）

状态：2026-11-15 写，命令 `ury-datapack` 已做并测试过；服务器和站点本身怎么建，等 12/1～12/4 的部署演练再补（本文只管"站点建好之后"）。相关：`docs/design/data-pack.md`、`launch-plan.md` 2.5 / 2.6 / 2.7。

**适用于**：排练站点（12/1 起）、正式站点（12/10～12/11 首次建）、12/18 用最终数据再应用一次。同一套手顺，命令可以重复执行（结果一样就是「変更なし」）。

**一句话**：备份 → 设置向导 → 看计划（只读）→ 你确认 → 加 `--apply` 应用 → 发初始密码 → `deploy_check` → 最后的确认项目。

### 「スタッフ」页的填写示例（三友寿司：5 个人，4 个账号；2026-11-16）

| 氏名* | ログインID（メール形式）* | 役割* | 言語 | 備考 |
|---|---|---|---|---|
| （店长的姓名） | `tencho@<待定>` | 店長 | ja | |
| （兼任收银和点单的人的姓名） | `reji@<待定>` | レジ担当 | ja | 兼任ホール。レジ担当能做ホール的全部，所以只填这一个角色 |
| （服务员的姓名） | `hall@<待定>` | ホール | ja | |
| 厨房 | `chubo@<待定>` | 厨房 | ja | 两位厨师共用，厨房屏幕固定一台 |

- **一人（一个账号）一行，一行一个角色。** 兼任收银和服务的人填「レジ担当」（2026-11-16 只读确认：收银员账号能用服务员的全部画面，登录后在画面下方点「ホール」切换）。
- **厨房是共用账号，只填一行**：「氏名」写「厨房」这样的名字（它会显示在画面上），不写某个人的姓名。两位厨师不各建账号：厨房屏幕是一台固定设备，一直开着同一个登录。共用账号的密码由店长和两位厨师一起定（培训材料第 0、3、4 页）。
- 「ログインID」必须是邮箱的形式（有 `@`），**不需要是真实存在的邮箱**，但不能重复；店员每次登录都要输入它，所以要短、好记。上面的 `<待定>` 等你给我登录 ID 和姓名后换掉。
- 「言語」是那个人看到的画面语言（ja / zh / ko / en），空着就是 ja。
- 店长的账号是「店長」（URY Manager）；它和服务器的 Administrator 是两回事，Administrator 只在设置向导和维护时用。

## 1. 二维码密钥：从哪里取、存在哪里、导入时怎么传

**是什么**：桌上二维码里的令牌是用它签名的。**两个站点的密钥相同，12/4 在排练站点印的二维码才能在正式站点读出来。**换了它，所有已贴的二维码立刻作废，要重新印。

**从哪里取（只做一次，12/1）**：在你自己的电脑上生成，不要在服务器上、不要在聊天里：

    python3 -c "import secrets; print(secrets.token_urlsafe(36))"

得到 48 个字符。**不要用开发站点或测试站点上的值**（它们曾对非 System Manager 可见，视为已泄露）；也不要自己编一个有规律的。

**存在哪里**：立刻存进**密码管理器**，条目名例如「三友寿司 二维码密钥」，备注写「换了它所有桌上二维码作废」。保管人是你；不给 Claude、不放 git、不发邮件和聊天。可以在另一个地方再存一份（比如装在信封里的纸）。

**站点上怎么存**：导入时写进 Self Ordering Profile 的密钥字段，这个字段是 Password 类型，**加密存在 `__Auth` 表里**（用站点的 `encryption_key`），表里只有 `*****`，接口和 Desk 都看不到。所以：
- 备份要**成套**保管（数据库备份 + `site_config_backup.json`），两个文件一起才能解出它；
- **万一密码管理器里的值丢了**，只要站点和它的 `encryption_key` 还在，可以读回来（会显示在屏幕上，别共享屏幕）：
  `bench --site <站点> execute frappe.utils.password.get_decrypted_password --args '["URY Self Ordering Profile","三友寿司","qr_signing_secret"]'`

**导入时怎么传**（命令**故意没有"把值写在命令行里"的选项**：命令行会进 shell 历史和进程列表）：

- **推荐：`--ask-qr-secret`**。命令会问两次（输入不显示），从密码管理器复制粘贴。不留任何文件。
- 备选：`--qr-secret-file <文件>`。文件里只有这个值，**权限必须是 600**（不是的话命令拒绝）：

      umask 077
      nano /home/frappe/pack/qr-secret.txt     # 粘贴，保存
      ...导入...
      shred -u /home/frappe/pack/qr-secret.txt  # 用完立刻删

- 长度不足 32 个字符或含空白，命令拒绝。
- **不指定**：Profile 在站点上还不存在时，命令**报错并停下**（防止悄悄用了随机生成的值，印好的二维码就读不了）。只有你**明确**要换新密钥（要重印二维码）时才加 `--new-qr-secret`。
- **Profile 已经在站点上**：传入的值必须和站点里的**完全一样**，否则报错，**不会改**。（换密钥是另一件事，要重印二维码，不通过导入做。）

**怎么确认两个站点的密钥一样**：① `deploy_check` 的 `self ordering profile` 一项用样例令牌验证签名（不显示密钥）；② 用手机流量扫一张在排练站点印的二维码，在正式站点上应看到「未開放」，而不是"无效的二维码"。

## 2. 在排练站点导出设备文件（排练站点上做，一次；平板有变化时重做）

    bench --site <排练站点> ury-datapack-export 三友寿司 /home/frappe/pack/ordering.json

文件权限自动是 600，**已有同名文件不覆盖**。文件里有：Profile 的设置、语言、年龄确认的商品分类、每台设备（id、类型、布局、固定桌子、**凭据哈希**）。**没有**二维码密钥和平板上的原始凭据。把文件拷到正式站点的服务器（`scp`，别经过聊天或邮件）。

**这样平板不用重新登记**：它们存的是原始凭据，站点里存的是哈希，哈希随文件过来，两边对得上。

## 3. 手顺

下面的 `<站点>` 是站点名（排练站点或正式站点）。

### 步骤 1：确认站点已经建好

    bench --site <站点> list-apps          # 应有 frappe、erpnext、hrms、ury
    bench --site <站点> execute ury.ury.api.deploy_check.run   # 现在有 FAIL 是正常的（菜单、桌子、账号还没进来）

### 步骤 2：先备份（站点还是空的也要做）

    bench --site <站点> backup

输出里有两个文件名（`...-database.sql.gz` 和 `...-site_config_backup.json`）。**记下来，成套保管**（见 `launch-plan.md` 2.6：加密的磁盘或云存储，不放在店员或顾客能拿到的地方，不给 Claude，不进 git）。

### 步骤 3：设置向导（浏览器，用 System Manager 账号）

打开 `https://<站点域名>/setup-wizard`（会跳到 `/ury/setup-wizard/0`），语言选「日本語」，填：公司名、T 开头的登录番号、**分店名**、**餐厅名**、地址、电话、会计年度、支付方式（现金、信用卡、PayPay、乐天 Pay 等）和结算账户。

**注意拼写要和 Excel 的「店舗」页完全一致**：分店名、餐厅名（导入时按名字找，找不到会报错"先走设置向导"，不会替你建）。

向导完成后，再跑一次 `deploy_check` 看一眼；仍然有 FAIL（菜单、账号等）是正常的。

### 步骤 4：把文件放到服务器，检查权限

    ls -l /home/frappe/pack/        # 目录 700，ordering.json 和 qr-secret.txt（如果用）600

### 步骤 5：看计划（**只读，什么都不写**）

    bench --site <站点> ury-datapack /home/frappe/pack/shop.xlsx \
      --ordering /home/frappe/pack/ordering.json \
      --images /home/frappe/pack/images \
      --public-url https://order.smst.app --local-url http://ury.lan \
      --ask-qr-secret

（没有图片就去掉 `--images`；`--public-url` / `--local-url` 只对**新建**的 Profile 有用，已有的 Profile 永远不改网址。）

输出按顺序分五段，每段一行汇总，下面是明细：

| 段 | 内容 |
|---|---|
| ■ サイトの設定 | 语言 ja、时区 Asia/Tokyo、国家 Japan、币种 JPY、关闭「邮件链接登录」 |
| ■ メニュー | 分类、厨房、商品、价格、中韩英名称、规格和加料 |
| ■ ルームとテーブル | 房间和桌子 |
| ■ セルフオーダーの設定と端末 | Profile、平板 |
| ■ スタッフのアカウント | 账号 |

每条前面是：**作成**（新建）、**更新**（改成表里的值）、**変更なし**（不显示，只算数）。`表にないもの（そのまま残します）` 是站点上有、表里没有的东西，**导入从不删除**。`※` 是提醒，`✗` 是错误。

**有任何 `✗` 就什么都不会写**：全部列出来，按句子改 Excel（工作表、第几行、哪一项都写了）或站点，重新来过步骤 5，直到没有 `✗`。常见的见第 4 节。

### 步骤 6：把计划给你确认

我（或你自己）把步骤 5 的输出给你看，确认这几点再往下走：
- 桌子数、房间名、菜单件数和几个价格是你填的；
- 账号：每人的邮箱、角色（店長 / レジ担当 / ホール / 厨房）对；
- 「作成」的账号数 = 新人数；老账号显示"变更なし"；
- 设备：平板的 device_id 和固定桌子对；
- `表にないもの` 里没有意外的东西（比如不该存在的测试桌子）；
- 提醒（※）逐条看过。

### 步骤 7：应用

命令和步骤 5 **一样，只加 `--apply`**：

    bench --site <站点> ury-datapack /home/frappe/pack/shop.xlsx \
      --ordering /home/frappe/pack/ordering.json --images /home/frappe/pack/images \
      --public-url https://order.smst.app --local-url http://ury.lan \
      --ask-qr-secret --apply

命令会再显示一遍计划，问「この内容で取り込みますか？」，回答 `y` 才继续。然后：
1. **自动备份**（写之前；输出里有文件名，记下来，和步骤 2 的一起成套保管）；
2. 按顺序写：站点设置 → 菜单 → 桌子 → Profile 和设备 → **账号（最后）**；
3. 全部成功才**提交一次**；任何一步出错，**全部撤回**（站点和写之前一样），也不会留下密码文件。
4. 最后自动跑 `deploy_check`，列出 FAIL。

加 `--yes` 可以跳过那个问题（脚本用；手工做的时候不要加）。

### 步骤 8：初始密码文件的保管和分发

只有**新建的账号**才会有初始密码；老账号的密码不动。密码写在**只有你能读的文件**里（命令的输出里写了路径，**不显示密码本身**）：

    sites/<站点>/private/initial-passwords-<日期-时间>.txt      # 权限 600；每行：邮箱  姓名  角色  初始密码（用 Tab 分隔）

- **分发**：每人一个密码，当面交，或用打印的小纸条；**不要把整个文件发到群里或邮件里**。（每人不同，随机 14 个字符，没有易混淆的字符。）
- **店员第一次登录后马上自己改密码**：`/update-password`（培训材料「第一天要做的事」第 1 条）。**系统不会强制改**（2026-11-15 决定不做），所以靠培训和你的抽查。
- **用完就删**：把密码存进密码管理器（只存还没改的人的，或全部存档），然后 `shred -u <文件>`。**这个文件不要拷到别的服务器，也不要放进备份**（默认的 `bench backup` 不含 private 文件，不要加 `--with-private-files` 之后忘了删）。
- **忘了密码**：没有办法找回；System Manager 在 Desk 里给那个账号重设一个新的。
- **再次导入**：已有的账号不再生成密码，也不会再写文件（所以文件只在第一次有）。

### 步骤 9：`deploy_check`

命令最后已经跑过一次，需要时再跑：

    bench --site <站点> execute ury.ury.api.deploy_check.ensure_ok

- **`0 failed` 才算过**（有 FAIL 会报错退出）；`WARN` 逐条判断；`INFO` 是要你确认的事项。
- **排练站点和开发站点**的 `public_url` 不是 https 时会 FAIL，这是预期的；正式站点不应该有。
- 正式站点还要做：`allow_error_traceback` 设为 0（`launch-plan.md` 2.7 第 9 条），否则 `error page` 一项 FAIL。

### 步骤 10：最后的确认项目（逐条打勾）

**数据**
- [ ] 步骤 2 和步骤 7 的两组备份文件都在，都是成套的两个文件，放在加密的地方
- [ ] 站点设置：语言 ja、时区 Asia/Tokyo、国家 Japan、币种 JPY（`deploy_check` 的 `site settings` 无 FAIL）
- [ ] 房间和桌子的数量和名字对（桌上二维码用桌子名，名字不能和印好的不一样）
- [ ] 菜单：件数对；抽查 3 道的税抜价和含税价（店内 / 外带，食品 10% / 8%，酒类 10%）
- [ ] 没有任何单据：POS Invoice、KOT、开班记录都是 0（正式站点从零开始）

**账号**
- [ ] 每个角色各用初始密码登录一次：店长、收银、服务员、厨房屏幕（只看到该看到的页面，语言对）
- [ ] 账号数 = Excel 的人数（`deploy_check` 的 `staff in a branch`、`staff without Desk`、`language of the staff` 无 FAIL / WARN）
- [ ] 初始密码文件已经交出去并 `shred -u` 删除；没有人从邮件或聊天里拿到它

**二维码和平板**
- [ ] 二维码密钥：`deploy_check` 的 `self ordering profile` 无 FAIL（样例令牌签名通过）
- [ ] 用手机**流量**（不连店内 Wi-Fi）扫一张贴好的二维码：打开 `https://order.smst.app/order/?t=…`，没有证书警告，显示「未開放」（店还没开班）
- [ ] 一台平板打开固定地址：显示等待画面（不用重新登记）
- [ ] 密钥临时文件（如果用了）已删除；shell 历史里没有密钥（命令没有这个选项，所以不会有）

**干净**
- [ ] Error Log 条数没有增加（对比步骤 2 之前）
- [ ] `deploy_check`：`0 failed`；WARN 和 INFO 都看过
- [ ] 一台收银电脑能打开 `/pos`，看到「开班」画面，**不要真的开班**（12/20 才开）

### 12/18 再应用一次

试营业中改了菜单或价格：改 Excel，在排练站点和正式站点**各跑一遍同样的手顺**（步骤 5 到 9）。命令是幂等的：改过的商品显示「更新」，其余「変更なし」，不会重复创建，账号不会再发密码。**桌子名和 Profile 名不能改**（改了二维码作废，导入会当成新的桌子）。

## 4. 出错时看这里

| 命令输出（节选） | 意思 | 怎么办 |
|---|---|---|
| `Excel ファイル「…」がありません` / 見出しが違います / シート…が見つかりません | 文件路径不对，或者表头被改了 | 用模板重新填，不要改第 1～4 行 |
| `分店「…」がサイトにありません。先にセットアップウィザードで…` | 向导里的分店名和 Excel 不一样 | 改 Excel 的「店舗」页，或在站点上改名，**拼写要一致** |
| `…のものと違います`（秘密鍵） | 站点里的二维码密钥和你传入的不同 | 先确认传入的是密码管理器里的值；**不要用导入改它**。真要换密钥，要重印所有二维码，另行处理 |
| `二次元コードの秘密鍵を指定してください` | Profile 在站点上还没有，又没给密钥 | 用 `--ask-qr-secret`；只有明确要换新密钥才加 `--new-qr-secret` |
| `秘密鍵のファイル…は、ほかの人も読める状態です` | 密钥文件权限不是 600 | `chmod 600 <文件>` |
| `端末「…」の認証情報が…違います` | 站点上这台平板的凭据被重新发过 | 弄清楚哪个是对的：要用文件里的，就在站点上删除那台设备记录再导入；要用站点的，就重新导出设备文件 |
| `アカウント「…」はすでに「…」の役割を持っています` | 老账号的角色和表里不同 | 不自动改，你决定：改 Excel，或在 Desk 里改角色 |
| `アカウント「…」は停止中です` | 账号被停用 | 不自动启用，你决定 |
| `パスワードのファイル「…」がすでにあります` | 初始密码的文件名已被占用 | 换 `--password-file` 的路径；旧的先确认能不能删 |
| `固定テーブル「…」がこのサイトにない` | 设备的固定桌子不在 Excel 的「テーブル」里 | 把桌子加进 Excel（命令会把同一个包里要新建的桌子算在内） |
| `取り込みに失敗したので、すべて元に戻しました` | 写入途中出错，已全部撤回 | 站点和写之前一样；看错误句子处理，再做一遍；备份在，不需要还原 |
| `deploy_check に FAIL があります（取り込みは済んでいます）` | 导入成功，检查有 FAIL | 逐条处理 FAIL，再跑 `deploy_check` |

**导入完成后发现整体不对**：用步骤 7 自动备份的文件还原（`bench --site <站点> --force restore <数据库备份文件>`，会**整站覆盖**，要先和你确认；同一个站点的 `encryption_key` 不变，所以密钥仍能解开）。

## 5. 命令速查

    # 排练站点：导出设备
    bench --site <排练站点> ury-datapack-export 三友寿司 /home/frappe/pack/ordering.json

    # 看计划（只读）
    bench --site <站点> ury-datapack <excel> [--ordering <json>] [--images <目录>] [--public-url <https://…>] [--local-url <http://…>] \
        (--ask-qr-secret | --qr-secret-file <文件> | --new-qr-secret)
